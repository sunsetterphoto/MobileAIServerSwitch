Mobile Server Switch

Monitor and control a workstation/laptop that's temporarily running as a server — mode, performance/power, remote access, services and firewall — all from your phone, over your Tailnet.

Six tabs, one control center

Everything you'd otherwise SSH in to check or change — surfaced in a Plasma widget, reachable from anywhere on your Tailnet.

Overview

Compact read-only summary: mode, performance, dGPU power draw, battery/AC, Tailnet IP, remote-access status, active services, Wake-on-LAN. Click through to any detail tab.

Performance

Power saver / balanced / performance presets via KDE PowerProfiles, plus a fine CPU-cap slider, dGPU runtime power management, WiFi/Bluetooth radios and Energy Performance Preference.

Mode

Server ⇄ Laptop switch. Server mode favors uptime; switching back to Laptop stops configured server services after a confirmation.

Remote Access

Status for SSH, RDP (KRDP), VNC, Sunshine, KDE Connect, Tailnet and Wake-on-LAN. On/off switches for RDP and Sunshine — SSH and Tailscale stay read-only, always.

Services

A configurable list of user/system services with live status, port reachability, and start/stop — configured once, not hardcoded.

Firewall

firewalld status at a glance plus targeted LAN-only blocks for configured apps. SSH stays allowed and the Tailnet is never affected — always.

Install

One command, idempotent, dry-run first if you like.

Quick install 
git clone https://github.com/sunsetterphoto/MobileServerSwitch.git
cd MobileServerSwitch
./install.sh

Requires jq and kpackagetool6; everything else (firewalld, rfkill, ethtool, tailscale, PowerProfiles, nvidia-smi) is optional and degrades gracefully. See the full README for manual install, configuration and uninstall.

Security model

The core promise: nothing here can ever lock you out.

  • SSH and Tailscale/the Tailnet are never switched or firewalled — no button, no rule, anywhere in the codebase. The firewall helper enforces a fixed/configured app whitelist and hard-refuses any rule touching port 22, regardless of configuration.
  • RDP is bound exclusively to the Tailnet, never 0.0.0.0. If no Tailnet address is detected, remote-desktop setup refuses to run at all rather than falling back to a wider bind.
  • Reads are unprivileged; writes go through scoped helpers. System-level changes (sysfs, rfkill, ethtool, firewalld) run exclusively via dedicated helper scripts under /usr/local/sbin, each enforcing a fixed whitelist — never a blanket sudo from the widget.
  • Risky live actions (CPU cap, service start/stop, radio switches, firewall rules) are all reversible and never change remote reachability.
